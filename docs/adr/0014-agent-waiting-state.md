# ADR-0014 — Состояние хода читается из транскрипта

**Дата:** 2026-09-23 · **Статус:** принято, пересмотрено 2026-09-24 · **Расширяет:** ADR-0013

> **Пересмотр 2026-09-24.** Состояние «ждёт тебя» снято. На точке в 6 pt ровный режим
> почти не отличался от пульсации 1 → 0,65, и по отзыву владельца индикатор «долго горит
> после конца работы и не отражает статус». Разбор хода остался и теперь делает другое:
> конец хода гасит точку сразу, без 20-секундного хвоста. Ниже — исходное решение,
> разделы про «ждёт», подтверждение и Reduce Motion для двух состояний — история.

## Что нужно

Сейчас точка в пилюле знает одно: агент пишет транскрипт. Когда ход кончился, она
гаснет через 20 с — и «закончил, твой ход» выглядит так же, как «ничего не происходит».
При нескольких параллельных сессиях именно так теряются минуты.

## Что измерено

2026-09-23, Claude Code 2.1.267, codex-cli 0.153.4, шесть свежих транскриптов каждого.

| Агент | Маркер «ход идёт» | Маркер «ход кончился» |
|---|---|---|
| Claude Code | `user` (запрос или результат инструмента), `assistant` со `stop_reason: tool_use` | `system` с `subtype: turn_duration` или `stop_hook_summary`, `assistant` со `stop_reason: end_turn` |
| Codex | `event_msg` → `task_started` | `event_msg` → `task_complete`, `turn_aborted` |

Прототип правила на живых данных: идущая сессия — «работает», все десять завершённых
Claude и пять из шести Codex — «ждёт»; в шестой маркеров хода нет вовсе.

После конца хода оба агента дописывают служебные строки: Codex —
`thread_settings_applied`, Claude — `last-prompt`, `mode`, `ai-title`. Сейчас каждая
такая запись зажигает пульсацию ещё на 20 с. Разбор хода это лечит: служебные строки
маркерами не являются и состояние не меняют.

**Субагенты** пишут отдельные транскрипты: у Claude — в `<сессия>/subagents/`, у Codex —
отдельный rollout, у которого в `session_meta.payload.source` есть `subagent`. Конец хода
субагента — не «твой ход», поэтому их маркеры игнорируются, а записи считаются работой.

## Решение

**Хуки не нужны.** На каждое событие FSEvents читается хвост изменившегося транскрипта,
и чистая функция домена находит последний маркер хода. Настройка у пользователя — нулевая,
ровно как у индикатора работы.

**Три состояния агента, «ждёт» важнее «работает»:**

| Состояние | Когда | Точка |
|---|---|---|
| ждёт | в какой-то сессии ход кончился после последнего раскрытия панели | горит ровно |
| работает | ход идёт и последняя запись моложе окна удержания | пульсирует |
| — | остальное | нет |

«Ждёт» перекрывает «работает»: из двух сессий одного агента та, что требует действия,
важнее. Точка одна на агента — ADR-0013.

**Раскрытие панели = «увидел».** Ожидание снимается, когда пользователь раскрывает
панель или когда в этой сессии начинается новый ход. Без подтверждения сессии, брошенные
неделю назад, горели бы вечно, и индикатор превратился бы в шум. По времени ожидание
не истекает: «твой ход» не становится менее верным через час.

**Отсчёт с запуска приложения.** Сессии, закончившие ход до старта Flowbar, не
показываются: событий о них не было.

**При Reduce Motion** пульсации нет у обоих состояний, поэтому «работает» горит ровно
на нижней непрозрачности пульсации 0,65, а «ждёт» — на полной. Для VoiceOver — «Claude
Code ждёт вас», «Codex работает».

## Что отвергнуто

| Вариант | Почему нет |
|---|---|
| Хуки `Stop`, `PermissionRequest`, `Notification` | нужна установка в два конфига с их слиянием; транскрипт даёт «конец хода» без настройки |
| Ожидание истекает через N минут | «твой ход» не устаревает; забытую сессию гасит подтверждение, а не таймер |
| Отдельная точка на каждую сессию | в крыле 16,5 pt места на две точки столбиком — ADR-0013 |

## Чем платим

**Запрос разрешения не виден.** Пока агент ждёт подтверждения команды, в транскрипте
висит вызов инструмента без результата — так же выглядит и долгая команда. Отличить
их по транскрипту нельзя. Это делают хуки; отдельное решение, если понадобится.

**Подтверждение грубое.** Любое раскрытие панели, даже случайное наведением, гасит все
ожидания.

**Хвост ограничен.** Если последняя строка длиннее хвоста (огромный вывод инструмента),
маркер не находится, и состояние сессии остаётся прежним.
