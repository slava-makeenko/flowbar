# ADR-0012 — Лимиты Claude Code и Codex читаются из файлов на диске

**Дата:** 2026-09-23 · **Статус:** принято · **Добавляет:** модуль «Лимиты», фаза 12 пайплайна

## Что измерено

macOS 26.5.2, Claude Code 2.1.267, codex-cli 0.153.4. Проверялось, откуда вообще можно
узнать остаток лимитов, не спрашивая пользователя.

| Источник | Ответ |
|---|---|
| `~/.codex/sessions/<ГГГГ>/<ММ>/<ДД>/rollout-*.jsonl` | **`rate_limits` в каждом `token_count`**: `primary` (окно 300 мин), `secondary` (10080 мин), у каждого `used_percent` и `resets_at`. В одном рабочем файле — 304 записи |
| `~/.claude/projects/**/*.jsonl` | `quotaLimits` с `rateLimitType` и `resetsAt` — **только в ответе с кодом 429**, то есть постфактум |
| JSON, который Claude Code передаёт statusLine-команде | **`rate_limits: { five_hour: { utilization, resets_at }, seven_day, seven_day_opus, seven_day_sonnet, spend_limit }`** |
| payload хуков Claude Code (`SessionEnd`, `PostToolUse`, …) | блока `rate_limits` нет |
| строки клиента Claude Code | живые проценты берутся с `/api/oauth/usage` по OAuth-токену |
| `claude --help`, `codex --help` | неинтерактивной команды со статусом лимитов нет: `/usage` и `/status` живут только в TUI |

Вывод: у двух агентов **нет общего источника**. У Codex данные уже лежат на диске и
пишутся сами. У Claude Code на диске их нет — но клиент отдаёт их наружу в statusLine.

## Решение

**Оба источника — файлы, оба читаются по требованию.**

| Агент | Файл | Кто его пишет |
|---|---|---|
| Codex | самый свежий `rollout-*.jsonl`, последняя запись с `rate_limits` | сам Codex, на каждом ходу |
| Claude Code | `~/.claude/flowbar-usage.json` | statusLine-скрипт, который пользователь ставит один раз |

Скрипт получает payload на stdin, откладывает из него `rate_limits` со временем снимка и
печатает свою строку состояния дальше — иначе пользователь потеряет статусную строку,
которой пользовался до нас:

```json
"statusLine": { "type": "command", "command": "~/.claude/flowbar-usage.sh" }
```

**Доступ — security-scoped bookmark на `~/.claude` и `~/.codex`**, тот же механизм, что
уже работает для папки скриншотов (ADR-0003, `ScreenshotFolderAccessing`). Закладка на
каталог покрывает и вложенные файлы, поэтому снимок Claude кладётся внутрь `~/.claude`:
одна закладка — один механизм на оба чтения.

**Показывается последний известный снимок и его возраст**, а не «текущие лимиты». Claude
обновляет данные только пока открыта сессия, Codex — пока идёт ход. `resets_at`
абсолютный, поэтому обратный отсчёт до сброса честен даже на старом снимке; после
`resets_at` окно считается обнулённым.

**Резидентного наблюдателя нет.** Файлы читаются при открытии модуля и пока он виден.
Второй постоянный таймер в приложении, где уже есть опрос пастборда (риск R5), не
заводится ради экрана, на который смотрят раз в час. Индикатору работы агентов в пилюле
наблюдатель нужен по определению — это отдельное решение, ADR-0013.

**Парсер терпимый.** Неизвестный ключ, `null` или пропавшее поле убирают одно окно, а не
ломают модуль: у рабочего аккаунта team в `rate_limits` было `primary: null`, и это
нормальный ответ, а не ошибка.

## Что отвергнуто

| Вариант | Почему нет |
|---|---|
| Самим звать `/api/oauth/usage` | нужен OAuth-токен Claude Code из Keychain — чужие учётные данные, под песочницей keychain-item другого приложения недоступен, эндпоинт недокументирован |
| Запускать `claude` / `codex` подпроцессом | команды со статусом лимитов вне TUI нет, а дочерний процесс наследует песочницу |
| Хуки Claude Code | в их payload нужного блока нет — он только у statusLine |
| Транскрипты `~/.claude/projects/**` | `quotaLimits` появляется только когда лимит уже исчерпан |
| Локальный прокси через `ANTHROPIC_BASE_URL` | перехват чужого трафика с токенами ради двух процентов на экране — несоразмерная цена |
| Писать снимок Claude прямо в контейнер приложения | закладка для Codex всё равно нужна, значит это второй механизм вместо одного; плюс запись чужого процесса в `~/Library/Containers` может упереться в TCC «доступ к данным других приложений» |

## Чем платим

**Claude требует ручной установки.** Без statusLine-скрипта модуль показывает только
Codex. Приложение не правит `~/.claude/settings.json` само: под песочницей это чужой файл,
а молча менять конфиг другого инструмента — не его дело. Вместо этого — пустое состояние
с кнопкой, которая кладёт готовую команду в буфер обмена; буфер у нас и так свой.

**Ещё два разрешения на папки.** Риск R4 («песочница против сценария „поставил и
работает“») усиливается: к папке скриншотов добавляются `~/.claude` и `~/.codex`.

**Форматы внутренние.** Схема rollout-файла Codex и набор ключей в payload statusLine
никем не обещаны и могут смениться с любым обновлением CLI. Деградация молчаливая:
модуль покажет «нет данных», а не неправильные проценты.

**Процентов в пилюле нет.** Они видны только в развёрнутой панели. Добавить
их в свёрнутую пилюлю — это её геометрия (спека §3.4) и постоянное обновление данных,
то есть отдельное решение, а не довесок к этой фазе. Индикатор того, что агент
работает прямо сейчас, в пилюле есть — ADR-0013.

## Вне объёма

Несколько аккаунтов у одного агента, spend-лимиты и overage, уведомление при приближении
к порогу, проценты в свёрнутой пилюле. Каждое — отдельное решение, когда модуль докажет,
что им пользуются.
