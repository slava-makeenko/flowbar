# ADR-0016 — Developer ID без песочницы; лимиты Claude — через `get_usage`

**Дата:** 2026-09-23 · **Статус:** принято · **Закрывает:** развилку ADR-0003 · **Пересматривает:** ADR-0012 (источник лимитов Claude)

## Почему сейчас

ADR-0012 брал лимиты Claude Code из снимка, который пишет statusLine. Замер показал:
вкладка Code десктопного приложения statusLine не запускает — за 40 минут работы снимок
застыл на 49 %, приложение Claude показывало 62 %. Флаг «Устарело» честен, но цифр
не даёт.

## Что измерено

2026-09-23, Claude Code 2.1.267. В протоколе SDK есть служебный запрос `get_usage`
с параметром `skip_behaviors` — в схеме клиента он описан «для вызывающих, кому нужны
только лимиты плана, например usage meter».

```
claude -p --input-format stream-json --output-format stream-json --verbose
→ {"type":"control_request","request_id":"u1","request":{"subtype":"get_usage","skip_behaviors":true}}
← control_response: rate_limits.five_hour.utilization = 68, seven_day = 46, plan pro
```

Модель не вызывается — лимит не тратится. Токен читает и обновляет сам Claude Code.
Сессия в истории не остаётся. Один вызов — запуск CLI, 1–3 с.

`claude setup-token` не годится: такие токены получают только `user:inference`, а для
лимитов нужен `user:profile`.

## Решение

**Дистрибуция — Developer ID, без App Sandbox.** В App Store приложение не идёт. Песочница
не пускает к `get_usage`: запущенный процесс наследует её, и `claude` не видит ни
`~/.claude`, ни Keychain, ни сети. ADR-0003 оценил откат в одну галочку — так и есть.

**Лимиты Claude — живой запрос `get_usage`, снимок statusLine — запасной.** Результат
новее побеждает: снимок читается каждые 10 с, живой запрос — при открытии экрана,
по кнопке ↻ и раз в минуту, пока экран открыт. Чаще нельзя: каждый вызов — запуск CLI.
Не нашёлся `claude` или запрос не ответил за 15 с — остаётся снимок, как в ADR-0012.

**Папки агентов читаются напрямую.** Выбирать `~/.claude` и `~/.codex` руками больше не нужно.

**Данные переезжают из контейнера.** Без песочницы Application Support и настройки
живут вне `~/Library/Containers/app.flowbar.Flowbar`. При первом запуске история,
картинки и вставки копируются, абсолютные пути картинок в базе переписываются, настройки
переносятся по ключам. Контейнер не удаляется: откат остаётся возможным.

## Что отвергнуто

| Вариант | Почему нет |
|---|---|
| Самим звать `/api/oauth/usage` с токеном из Keychain | чужие учётные данные; обновив просроченный токен, Flowbar мог бы разлогинить Claude Code |
| Песочница плюс помощник без песочницы (XPC, LaunchAgent) | второй процесс и та же поверхность атаки ради песочницы, которая больше ничего не бережёт |
| Остаться на снимке statusLine | цифры точны только после хода в терминальном `claude` |

## Чем платим

**App Store закрыт.** Для выпуска нужны аккаунт разработчика, нотаризация и настоящий
bundle id — последний и так был открытым пунктом приёмки.

**Приложению доступна вся домашняя папка.** То, от чего берегла песочница, теперь держится
на дисциплине: системные API — только в `FlowbarData`, чтение — только известных путей.

**`get_usage` экспериментальный.** Может измениться с любым обновлением Claude Code.
Деградация — к снимку statusLine, то есть к ADR-0012.

**Автовставка ⌘V** из ADR-0003 становится возможной, но в объём не входит.
