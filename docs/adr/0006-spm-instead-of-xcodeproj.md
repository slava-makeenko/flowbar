# ADR-0006 — Приложение собирается из SPM, `.xcodeproj` не заводится

**Дата:** 2026-08-06 · **Статус:** принято · **Отклонение от:** спека §12

## Контекст

Спека §12 предполагает Xcode-таргет приложения рядом с пакетом. Регламент §2.1 требует,
чтобы границы слоёв держал компилятор через отдельные таргеты SPM.

## Решение

Приложение — `executableTarget` в том же `Package.swift`. Бандл `Flowbar.app` собирается
скриптом `Scripts/make-app.sh` из бинарника, `Info.plist` и ресурсов. Файл `.xcodeproj`
в репозиторий не кладётся.

## Почему

- Всё, включая приложение, собирается и проверяется одной командой из терминала:
  `swift build`, `swift test`, `swift-format lint --strict`. CI не требует Xcode-проекта.
- `project.pbxproj` — генерируемый по сути файл, который плохо ревьюится и конфликтует
  при слиянии. Раскладка слоёв уже описана декларативно в `Package.swift`.
- Xcode открывает `Package.swift` как проект напрямую: редактирование, отладка и превью
  SwiftUI работают без отдельного проекта.

## Следствия

- Подпись, нотаризация и загрузка в App Store делаются `codesign` / `notarytool` /
  `xcrun altool` поверх собранного бандла, а не кнопкой Archive. Это работа фазы 11.
- Если на фазе 11 выберут App Store и потребуется Archive-флоу, Xcode-проект-обёртка
  добавляется поверх пакета — слои при этом не трогаются.

## Обратимо

Да. Пакет остаётся источником истины по слоям в обоих случаях.
